# 다국어·단위 설정과 공개 항공 데이터

## 화면 언어

`src/common/preferences.js`가 언어와 단위를 공통 반응형 상태로 관리합니다. `/settings/language`의 선택은 패스포트 숫자 타이틀, 통계 제목·범례·정렬 탭, 목록·상세·예약, 설정·알림, 달력, 지도 안내에 즉시 반영됩니다. 한국어·영어·일본어를 지원하며, 기기 언어는 `navigator.language`의 언어 코드를 사용합니다. 지원하지 않는 기기 언어는 영어로 표시합니다.

설정은 같은 출처(origin)의 `localStorage` 키 `flighty-preferences`에 저장하여 페이지 이동·새로고침 후에도 유지합니다. 저장소가 차단되어도 현재 화면에서는 변경할 수 있습니다. 잘못된 저장값은 기본값으로 처리합니다. 기본값은 기기 언어, 거리 `km`, 속도 `km/h`, 고도 `m`입니다. 색상 테마와 예약 편집은 기존처럼 새로고침 시 초기화됩니다.

번역은 `src/locales/messages.json`의 영어 원문 키와 `en`, `ko`, `ja` 값으로 관리합니다. 템플릿은 `$t("Flights")`, 공통 모듈의 계산 문구는 `t("Terminal {terminal}", { terminal: "2" })`처럼 사용합니다. 번역이 없으면 원문을 표시합니다. 별도 i18n 의존성 없이 기존 공통 모듈 구조를 따릅니다. 날짜·요일·월·숫자·국가명은 선택 언어의 `Intl` 포맷을 사용합니다. 공항명·도시명·항공사명의 번역도 같은 사전에 있습니다.

`BaseTabItem` 등의 표시 문구만 번역합니다. `ALL-TIME`, `Flights`, `Window`, `Economy` 등 선택·집계 키, 라우트, 항공사·공항 코드, 편명, 등록번호, 예약번호, 좌석, 사용자 이름은 원본을 유지합니다. 언어를 바꿔도 정렬·필터·예약 값이 달라지지 않습니다. 포트폴리오 소개 글과 `/component`의 개발용 설명은 제품 데이터 타이틀 번역 대상에 포함하지 않았습니다.

문구를 추가할 때는 영어 원문으로 키를 만들고 세 언어 값을 작성합니다. 문장 중간에 숫자나 시간만 끼워 넣지 않고 `{recorded}`, `{total}` 같은 매개변수로 전체 문장을 번역해야 언어별 어순이 자연스럽습니다. 기존 컴포넌트의 문자열 props를 유지하기 위해 과거 예시의 `2h 30m`, `1,000 km`, `2 flights` 형식도 공통 표시 함수에서 처리합니다. 새로운 항공편 계산에는 아래 전용 포맷 함수를 사용합니다.

## 단위

`/settings/units`에서 거리 `km / mi / nm`, 속도 `mph / km/h / kt`, 고도 `ft / km / m / FL`을 선택합니다.

- `formatDistance(km)`: 패스포트 누적 거리, 항공편 상세·노선 이력, 항공편 통계 합계·평균·최단/최장·순위 막대에 적용합니다. 순위·합계 계산은 항상 km 기준이며 표시할 때만 환산합니다. 상세 통계의 보조 거리는 km 선택 시 mi, 그 외 선택 시 km로 함께 표시합니다.
- `formatSpeed(kmh)`, `formatAltitude(meters)`: 설정 화면의 변환 예시에 사용합니다. 현재 CSV와 adsbdb 기체 메타데이터에는 실시간 속도·고도 측정값이 없어, 실제 항공편의 측정값을 임의 생성하지 않습니다. 예시는 속도 900 km/h, 고도 10,668 m(35,000 ft)입니다. 향후 측정값도 같은 함수로 표시할 수 있습니다.
- 1 mi = 1.609344 km, 1 nm = 1.852 km, 1 kt = 1.852 km/h, 1 ft = 0.3048 m입니다. FL은 100 ft 단위로 표기합니다. 예시의 FL 350은 길이 환산이며, 실제 비행 고도에서 기압 보정을 계산하는 기능은 아닙니다.
- 일반 거리는 정수, 순위는 선택 언어의 compact 표기, 속도·고도는 정수(고도의 km만 소수 둘째 자리)로 표시합니다. 비행시간은 언어에 따라 `1h 30m / 1시간 30분 / 1時間 30分`으로 표시하며 거리·속도 설정과 독립적입니다. 미기록 시간은 `—`입니다.

## 공항과 항공사 데이터

수동 기준 정보 대신 개발 의존성의 무료 공개 데이터셋을 사용합니다. 브라우저에서 거대한 전체 데이터셋을 읽거나 공항 API를 매번 요청하지 않습니다.

- 공항: [airport-data-js 4.0.0](https://github.com/aashishvanand/airport-data-js). IATA·ICAO·공항명·위도/경도·고도·국가 코드·대륙·IANA 시간대·홈페이지를 가져옵니다. [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)이며 작성자는 Aashish Vanand입니다.
- 항공사: [airline-codes 1.1.6](https://github.com/npow/airline-codes)의 [OpenFlights 항공사 데이터](https://openflights.org/data.php). 항공사명·IATA·ICAO·ATC callsign·국가를 가져옵니다. 패키지 코드는 ISC, 원본 데이터는 [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/)(개별 콘텐츠 DbCL)입니다. 데이터 라이선스는 코드 라이선스와 구분합니다. 공개 배포하는 파생 데이터베이스에는 ODbL 출처 표시·동일조건 공유 등 원본 조건을 적용합니다.
- 기체: 기존 [adsbdb](https://github.com/mrjackwills/adsbdb) 등록번호 조회를 유지합니다. 동작과 실패 처리는 [임시 데이터 가이드](temp-data.md#기체-공개-데이터-조회)를 참고합니다.

`Settings > Data sources`에서도 공항·항공사 출처와 라이선스에 접근할 수 있습니다. 원본 데이터에서 필요한 코드만 추리고 필드명과 누락값을 정리한 변경 사항은 이 문서와 `src/data/reference/README.md`에 명시합니다. 공개 데이터는 갱신 시점에 따라 실제 정보와 차이가 있을 수 있습니다. 공항 UTC 고정 오프셋 대신 IANA 시간대를 사용해 날짜별 서머타임을 계산합니다.

### 생성 파일과 보완 정보

`scripts/generate-aviation-data.mjs`가 항공편 JSON과 표시용 설정에 등장하는 코드만 추려 아래 파일을 생성합니다. 현재 공항 26개, 항공사 9개입니다.

- `src/data/reference/airports.json`, `airlines.json`: 외부 데이터에서 생성한 기준 정보. 직접 편집하지 않습니다. 생성 결과도 저장하여 버전 관리하고 오프라인 화면 표시가 가능하게 합니다. 전체 npm 데이터셋은 브라우저 번들에 포함하지 않습니다.
- `src/data/airport-display.json`: 라이브러리에 도시 필드가 없어 기존 화면용 도시 이름만 보완합니다. 공항 위치·국가·시간대는 모두 외부 데이터 값입니다.
- `src/data/airline-details.json`: 라이브러리가 제공하지 않는 로컬 로고, 동맹, 한국어 별칭, 공식 전화·홈페이지·SNS만 보완합니다. 공식 링크의 출처는 각 항목의 `sources`에 남깁니다. 확인되지 않은 연락처는 만들지 않습니다.
- `src/common/airports.js`, `airlines.js`: 생성 정보와 표시용 보완 정보를 연결하고 번역된 이름을 제공합니다. ICAO·IATA·callsign 검색은 언어와 관계없이 원래 코드로 동작합니다.
- `src/common/flights.js`: 공항 좌표로 대권거리(km)를 계산하고 항공편을 연결합니다. 기존 수동 거리 필드는 제거했습니다. 실제 운항 경로와 다르므로 `≈`와 대권거리 안내를 유지합니다.

항공사 IATA가 중복되면 활성 여객 항공사만 선택하고 화물 항공사를 제외합니다(예: SQ). 하나로 결정되지 않거나 좌표·시간대가 없으면 생성에 실패하도록 하여 잘못 연결한 상태로 빌드하지 않습니다. 원본이 갱신되어 코드가 재사용되면 해당 항공편 시점에 맞는 레코드인지 확인해야 합니다. 항공편 기록의 과거 기종은 현재 기체 조회 응답으로 덮어쓰지 않습니다.

패키지의 AS 호출부호가 `Inc.`인 것처럼 영문·숫자·공백·하이픈 외 문자가 포함된 값은 잘못된 호출부호로 보고 `null`로 제외합니다. 확인되지 않은 호출부호를 추정하여 채우지 않습니다. 원본의 활성 여부도 현재 운항을 보장하지 않습니다.

### 갱신 방법

```sh
npm ci
npm run data:refresh
npm run build
```

`predev`와 `prebuild`에서도 생성 스크립트를 실행합니다. 공항·항공사는 네트워크 조회 없이 설치된 패키지와 `package-lock.json`의 버전을 사용합니다. 기체는 등록번호별 adsbdb 스냅샷(`reference/aircraft.json`)을 재사용하고 캐시가 없는 번호만 무료 API로 보완합니다. `npm run data:aircraft`로 기체 전체를 갱신할 수 있으며 통신 실패 시 이전 스냅샷을 유지합니다. 최신 공항·항공사 원본을 반영할 때는 패키지를 명시적으로 갱신한 다음 `npm run data:refresh`를 실행하고 생성 JSON의 코드·좌표·시간대·callsign 변경을 검토합니다. 새 항공편에 새 공항·항공사 코드를 넣으면 자동으로 생성 대상에 포함됩니다. 도시 별칭·공식 연락처·번역은 필요한 경우 별도로 보완합니다.
